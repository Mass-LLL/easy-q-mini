# EasyQ — 一个简单的排队取号小程序

EasyQ 是一个免费、无服务端的线下排队取号微信小程序：老板建一个队列、手机屏幕上亮出二维码，客人扫码拿号，老板按序叫号。

**它用老板的手机替代了店里那台打票机 / 取号机**——不买硬件、不装纸、不维护，一个二维码就是一台取号机。客人端不装 App（小程序即扫即用），老板端只需要一台亮着屏幕的手机。

## 背景与核心取舍

线下排队（餐馆、景区、办事窗口）的传统方案是打票机：买机器、装热敏纸、定期维护。EasyQ 想验证一件事：**排队取号既不需要硬件，也不需要服务器。**

核心取舍是：**把计算和状态全部下推到客户端，后台只用一个免费 MQTT broker 做消息管道**，不部署任何自有服务。

- **没有发号权威**。号码不是"分配"的，是每台设备根据同一组入队消息本地算出来的（按 `(时间, 设备id)` 全序排序）。因此不需要服务器、不需要计数器落盘，**老板离线时客人照样能拿到号**——老板只需要在"叫号"那一刻在线。
- **不提供「取消排队」**。取了号就像拿了一张纸质小票，入队消息只增不删。换来的是"号码永远单调、不会因有人离开而前移"这条不变式。
- **为取舍买单**。没有服务端的代价是实打实的：客人首次取号要回放整条队列的入队消息（流量随队列长度平方增长）、broker 凭证在客户端里等于公开、没有小程序码导致扫码入口多两步。完整的取舍与已知缺口见 [DESIGN.md](DESIGN.md)（尤其文末「后续加固清单」）。

一句话：**这套设计不是在省服务器，而是把复杂度搬到一个不用半夜起来处理的地方。**

### 这个取舍适合谁

「零服务端」是**为免费、有限资源这个前提选**的：不买服务器、不备案、不运维，成本按 broker 用量走——没人用就是 0，边际成本趋近于零，才能在有限资源上支撑尽可能多的流量。

如果你**有自己的服务器、愿意承担运维（自建场景），不要抄这套方案**——轻量后台 + Redis `INCR` 是更合理的选择：服务端一把 `INCR` 就是发号权威，号码由服务端分配，客户端那一整摞复杂度（全序排序、静默窗口、定稿标记、自愈机制）全部消失；客人端流量从 O(队列长度) 降到 O(1)，取消排队、跨天队列退化成普通 CRUD，**健壮性、扩展性都更好**。本方案的逻辑是「用客户端复杂度换掉运维责任」，不是「无后台比有后台好」——有资源、有运维能力时，后台方案在工程上更优。

## 功能

| 角色 | 功能 |
| --- | --- |
| 老板 | 创建队列（每天最多 20 个）、手机屏幕亮二维码（防息屏）、叫下一位、等待人数、「重新统计」（人数上报丢了时直接数入队消息） |
| 客人 | 扫码取号、实时位置（前面还有几位 / 下一位就是你 / 已到号）、过号与已结束记录、当天可以重新排队 |
| 双方 | 队列与二维码 24 小时自动失效；无账号、无隐私采集，只有号码 |

## 已知限制（摘录）

- **P0（发布前必须验证）**：broker 域名能否加入小程序「socket 合法域名」白名单（需要 ICP 备案，免费 EMQX 的海外域名大概率没有）；《用户隐私保护指引》需声明 `wx.scanCode`。
- **P1（有真实用户后）**：共享 broker 凭证可被解包获取；免费额度按会话分钟/流量计费；到号提醒需要服务端（微信一次性订阅消息）。
- **P2（规模化后）**：改本机时钟可插队；同队列客人可伪造叫号消息；小程序码需要服务端。

完整清单及每条的取舍依据见 [DESIGN.md](DESIGN.md)「后续加固清单」。

## 技术栈

- 微信小程序（原生，`componentFramework: glass-easel`，无第三方组件）
- MQTT 5（QoS 1 + retained + 24h 自动过期），`wxs://` transport
- `libs/mqtt.js`（打过补丁的 vendored 产物）与 `libs/qrcode.js` 直接入库，`dayjs` 走 npm + 构建 npm
- **零服务端代码**

## 快速开始

```sh
npm install    # 之后在微信开发者工具里执行「工具 → 构建 npm」重建 miniprogram_npm/
npm test       # logic + protocol + resilience 三套纯 node 测试，不需要开发者工具
```

1. 微信开发者工具导入本目录（appid `wxaaf13feaac4c6a42`，或换成你自己的）
2. 在 `utils/config.js` 填入你自己的 MQTT broker（参考 EMQX Serverless 免费额度；仓库里现有一组作者在用的凭证，请换成自己的）
3. 联调时开发者工具可勾选「不校验合法域名」；**发布前必须把 broker 域名加入「socket 合法域名」白名单**（P0 验证项，见上）

体验主链路：老板端「我创建的」建队列 → 手机亮出二维码 → 另一台设备扫码取号 → 老板叫下一位。

## 项目结构

```
utils/    config（broker 配置 + 时间/重试旋钮）、mqtt 单例客户端、本地存储、排序、id、二维码
pages/    queue 我排过的（客人）/ mine 我创建的（老板列表）/ host 老板端队列详情
libs/     vendored 依赖（mqtt.js 已打补丁，升级用 npm run vendor:mqtt）
test/     logic / protocol / resilience + harness（内存 broker 与故障注入）
```
